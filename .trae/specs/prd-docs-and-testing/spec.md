# PRD 文档与黑盒测试 Spec

## Why
项目需要正式的产品文档和用户手册来支撑演示和交付，同时需要通过系统化的黑盒测试验证所有页面功能可用，确保演示时不会出现白屏或功能异常。

## What Changes
- 新增 `prd/` 目录，包含产品文档、用户手册、测试用例、测试结果
- 基于项目现有代码、README、知识库、演示流程文档，梳理完整的产品文档
- 基于用户手册编写覆盖所有页面的测试用例
- 执行 Web 页面黑盒测试（使用浏览器自动化工具）
- 测试结果写入文件，包含通过/失败/截图
- 根据测试结果修复 Bug，修复后重新测试通过

## Impact
- Affected specs: 无（新增文档）
- Affected code: 仅修复测试中发现的 Bug，不新增功能

## ADDED Requirements
### Requirement: 产品文档
系统 SHALL 提供一份产品文档（`prd/product-doc.md`），包含：
- 产品概述与定位
- 技术架构说明
- 功能模块清单（20 个页面，5 大业务分组）
- RBAC 权限体系说明（5 个角色，56 个权限码，16 个权限组）
- 数据模型概览
- API 接口概览

### Requirement: 用户手册
系统 SHALL 提供一份用户手册（`prd/user-manual.md`），包含：
- 快速入门（启动、登录、切换角色）
- 每个页面的操作指南（页面功能、操作步骤、权限要求）
- 角色与权限对照表
- 常见问题

### Requirement: 测试用例
系统 SHALL 提供一份测试用例文档（`prd/test-cases.md`），覆盖：
- 每个页面的基本渲染（页面加载不白屏）
- 每个页面的核心交互（搜索、筛选、分页、Modal 打开/关闭）
- 角色切换后的权限生效（按钮可见性、接口权限）
- 边界场景（空数据、异常数据）

### Requirement: 黑盒测试与结果
系统 SHALL 通过浏览器自动化工具执行黑盒测试，并将结果写入 `prd/test-results.md`，包含：
- 每个测试用例的执行结果（通过/失败）
- 失败用例的截图和错误描述
- 修复后的回归测试结果

### Requirement: Bug 修复
测试中发现的 Bug SHALL 被修复，修复后重新执行黑盒测试，确保所有用例通过。
