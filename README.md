# Nexus 客户运营管理台

一套完整的多租户 SaaS 运营管理后台，用于验证 Trae 在企业级研发场景中的全栈能力。

## 项目规模

| 指标 | 数值 |
|------|------|
| 总代码行数 | **30,000+ 行**（TypeScript + TSX + CSS） |
| 功能页面 | **20 个**（五大业务分组） |
| API 路由 | **18 个**模块 |
| 后端服务 | **16 个**服务层 |
| 测试用例 | **355 个**（13 个测试文件） |
| 前端组件 | **33 个**可复用组件（含 4 个 SVG 图表组件） |

## RBAC 权限体系

| 角色 | 说明 | 典型权限 |
|------|------|----------|
| platform_admin | 平台管理员 | 全部 56 个权限码，可管理所有租户和用户 |
| tenant_admin | 租户管理员 | 管理本租户用户、审批、发布、订阅 |
| auditor | 审计员 | 只读访问所有模块，可导出审计日志 |
| release_manager | 发布经理 | 审批操作、部署与回滚发布 |
| member | 普通成员 | 最小查看权限，仅可查看列表 |

前后端基于共享权限矩阵（`packages/shared/src/rbac.ts`）统一判断，前端按钮可见性由 `can()` 控制，后端接口由 `requirePermission()` 中间件拦截。

## 快速开始

```bash
# 安装依赖
pnpm install

# 启动后端 API（端口 3001）
pnpm dev:api

# 启动前端管理台（端口 5173）
pnpm dev:web
```

## 测试

```bash
# 运行全部测试（355 个用例）
pnpm test

# 仅运行 API 测试
pnpm test:api

# 类型检查
pnpm typecheck
```

## Trae 功能演示：黑盒测试提示词

以下 5 个提示词可直接交给 Trae 执行，验证 Trae 的浏览器自动化测试能力。每个案例约 1 分钟。

> **重要**：请使用 **browser_use agent** 执行以下测试。如果页面显示"无权限或无客户数据"，优先点击刷新按钮重试，不要直接判定为失败。

### 案例 1：全页面渲染检查

```
使用 browser_use agent，按 prd/test-cases.md 中的 TC-G01 用例，
以平台管理员身份依次访问所有页面，检查每个页面是否正常渲染（无白屏、无报错）。
如果页面显示"无权限或无客户数据"，先点击刷新按钮重试。
输出每个页面的 PASS/FAIL 结果。
```

### 案例 2：RBAC 权限矩阵验证

```
使用 browser_use agent，按 prd/test-cases.md 中的 TC-R01、TC-R02 用例，
访问角色权限页面，验证角色卡片渲染和权限矩阵 Modal 的完整性。
截图保存。
```

### 案例 3：角色切换 + 权限隔离

```
使用 browser_use agent，按 prd/test-cases.md 中的 TC-G02（角色切换）
和 TC-P01~TC-P07（权限测试）用例，验证角色切换功能正常，
且不同角色看到的操作按钮符合 RBAC 矩阵预期。
注意：切换角色后等待页面完全加载再导航，避免状态未更新。
截图保存关键步骤。
```

### 案例 4：审批状态机

```
使用 browser_use agent，按 prd/test-cases.md 中的 TC-A01~TC-A07（审批中心）
和 TC-E02（重复审批边界）用例，验证审批的创建、通过、拒绝流程，
以及重复操作的错误拦截。截图保存关键步骤。
```

### 案例 5：多角色权限对比

```
使用 browser_use agent，按 prd/test-cases.md 中的 TC-P01~TC-P07（权限测试）用例，
依次切换平台管理员、普通成员、审计员、发布经理，
对比各角色在 /tenants、/roles、/audit-logs、/releases 页面的权限差异。
注意：每次切换角色后等待页面完全加载再导航。
输出角色权限差异对比表。
```
