# 产品概述

本项目是 Nexus 客户运营控制台，一个面向 B2B SaaS 订阅业务的客户、租户、用户、审批、发布、风险工单与审计运营后台。系统用于呈现企业管理台的真实业务上下文，同时保留若干可被 Agent 识别和修复的预置缺陷。

## 目标用户

- 平台管理员（platform_admin）：拥有全部能力，能够修改租户计划、管理用户角色。
- 租户管理员（tenant_admin）：在当前租户内管理用户、查看审批、查看发布记录。
- 审计员（auditor）：只读访问，查看用户、审批、发布记录与审计日志。
- 发布经理（release_manager）：查看审批、通过/拒绝审批、部署与回滚发布。
- 成员（member）：最小查看权限，仅能看到租户、用户、审批列表。

## 模块结构

| 模块 | 说明 |
| --- | --- |
| 认证与会话 | 通过 `x-user-id` 请求头注入当前用户（演示用途） |
| 租户与组织 | 租户 ID 区分隔离；平台管理员可修改租户计划 |
| 客户画像 | 展示行业、套餐、健康分、合同到期、CSM、席位、月活与 ARR |
| 用户与角色 | 一个用户可拥有多个角色 |
| 权限控制 RBAC | 角色决定权限集合；前后端均基于共享权限矩阵判断 |
| 审批工作流 | 创建、通过、拒绝审批；可能存在状态一致性问题 |
| 审计日志 | 记录关键写操作 |
| 发布与变更记录 | 版本、环境、状态；可执行发布与回滚 |
| 风险工单 | 聚合客户支持、安全、采用率、账单和发布风险，按 SLA 排序 |
| 最近活动 | 串联用户、审批、发布、风险和审计事件，辅助工作台快速判断态势 |

## 关键约定

1. 权限校验以后端为准，前端展示仅为"友好隐藏"。
2. 前后端通过 HTTP API 通信，返回均为 JSON。
3. 所有写操作（POST/PUT/DELETE）都会写入审计日志。
4. 演示数据使用内存存储，进程重启即还原为种子数据。
5. 工作台指标基于 seed/store 实时计算，包括 ARR、活跃客户、风险工单、发布健康度与平均客户健康分。
6. 已知缺陷仍保留在权限、API 契约、审批状态机、审计摘要和 CI 配置中，便于后续验证 Agent 修复能力。
